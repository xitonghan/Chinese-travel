# 数据发布指南（给内容维护者）

> 本指南面向"改内容的人"——不需要懂 Flutter，会跑 Python 命令即可。
> 目标：**App 发一次不用动，内容随时改、随时发。**

---

## 1. 架构一句话

```
App（框架，稳定）  ←读取—  数据包 pack_v1.json + 音频（可变，经常发）
```

- App 里没有任何写死的课程、词汇、界面文案——全部读数据包。
- 数据包由 `tools/build_pack.py` 生成，**改内容只改这一个文件**。
- 音频（标准音）是普通 mp3，放进 `assets/audio/` 即可。

## 2. 日常改内容三步

```bash
# ① 编辑 tools/build_pack.py：课程、词汇、三语文案都在里面
# ② 生成数据包
python tools/build_pack.py
# ③ 提交推送（GitHub Desktop：写说明 → Commit → Push）
```

推送后 GitHub Actions 自动构建新 APK，从 Actions 页面下载即可分发。
**App 代码一行都不用改。**

## 3. 各类修改怎么做

| 想改什么 | 改哪里 | 之后要不要重跑 extract_f0 |
|---|---|---|
| 界面文案（阿/英） | `build_pack.py` 的 `UI` 字典 | 不用 |
| 课程步骤/句子译文 | `build_pack.py` 的 `LESSON_01` | 不用 |
| 增删词汇 | `build_pack.py` 的 `WORDS` | 不用 |
| 换/加标准音 | mp3 放进 `assets/audio/sentences/` 或 `words/`，文件名与 `build_pack.py` 引用一致 | **要** |
| 新增跟读句子 | 加音频 + 在 `build_pack.py` 加句子条目 | **要** |

```bash
# 有音频变化时，重跑 F0 提取（依赖 pip install miniaudio numpy）
python tools/extract_f0.py
python tools/build_pack.py
```

## 4. 从零生成一段新语音（可选）

```bash
pip install edge-tts
python -c "import asyncio, edge_tts; \
asyncio.run(edge_tts.Communicate('你好，我是来出差的。', 'zh-CN-YunyangNeural').save('我的音频.mp3'))"
```

把生成的 mp3 按命名规范放入 `assets/audio/`，再走第 3 节表格的流程。

## 5. 数据热更新（外部覆盖，进阶）

`lib/data/content_loader.dart` 已实现优先级：

```
手机应用数据目录/content/pack_override.json   （最高优先）
        ↓ 没有则用
App 内置 assets/content/pack_v1.json
```

把整份数据包命名为 `pack_override.json`、连同样式相同的
`audio/` 子目录，一起推进手机的
`/Android/data/<包名>/files/content/`（或用 adb push），
App 重启后即用新数据——**不用重装 APK**。
这是为将来"数据服务器只推数据"准备的机制，当前版本先留好。

## 6. 版本与兼容

- 数据包 `pack.min_app_version` 声明最低 App 版本；App 版本低于它时数据不生效
  （防新数据字段把老 App 弄崩）。
- 改数据结构（比如给单词加字段）时，同步改 `lib/data/models.dart` 并提升
  `min_app_version`。

## 7. 检查清单（发布前）

- [ ] `python tools/build_pack.py` 输出无报错，`跟读句 N（含 F0 N）` 数字符合预期
- [ ] 阿语文案让阿拉伯朋友过目（尤其称谓、语气）
- [ ] Actions 构建变绿，APK 在真机上跑一遍：能出声、能录音、对比图能出来
